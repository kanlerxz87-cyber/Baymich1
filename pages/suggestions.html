Suggestions for improving the site

Review these suggestions and choose the best path before implementing any changes. None are committed; each needs a decision.

A. Add an interactive map

A map with pins for each starred restaurant and Key hotel would make clusters instantly visible. Use relative URLs and have the dev server proxy them; never call localhost from browser-facing code. Consider Leaflet (free, open source) with a GeoJSON file of venue addresses geocoded from official sources.

  • Pros: cluster visualization, mobile-friendly trip planning, direct differentiation from a plain table.
  • Cons: geocoding must be verified per address; map tiles need a provider (attribution required); adds build complexity.

B. Complete missing prices, hours & social links

Most rows still have price/hours flagged unverified. Before publishing as "complete," fetch each venue's official site (or MICHELIN Guide page) and fill in: tasting-menu price, service charge, days open, hours, exceptions (holidays/closures), and YouTube/TikTok/Instagram handles.

  • Priority: the 5 three-star and 11 two-star restaurants (highest decision value).
  • Mark anything still unconfirmed as blank/unverified — never infer.

C. Add a "total all-in cost" estimate column

Currently the table shows food-only estimates for 2 adults before tax, service and drinks. Add a clearly-labeled "all-in est." column (add ~20–22% service + ~8.625% SF sales tax + drinks/wine pairing). Label it an estimate and show the formula so users aren't misled.

D. Handle closed / moved venues clearly

Osito (closed permanently) and The Shota (temporarily closed since Mar 2025) are flagged. Sons & Daughters moved to 2875 18th St in Nov 2025. Add a visible "Status" badge (Open / Temporarily closed / Closed / Moved) and a "last verified" date on each row.

E. Add Bib Gourmand & Recommended restaurants to the main dashboard

Currently Bib Gourmand is a separate page. Consider a toggle on the restaurants page to show "starred only" vs "starred + Bib Gourmand + Recommended" so users can see value options alongside stars.

F. Hotel ranking is Baymich1 analysis, not MICHELIN

The "nearby starred restaurants" hotel ranking is our own analysis. Label it clearly as non-official on the hotels page (already done) and consider adding actual hotel prices from official hotel sites if you want a cost comparison.

G. Mobile performance & accessibility

Tables are responsive but wide; on very small phones consider a card view per restaurant instead of a table. Keep color contrast above WCAG AA (the Michelin red on white and gold badges were checked). Add image alt text and ARIA labels to the drawer menu (already partially done).

H. GitHub Pages publishing

Enable GitHub Pages on the repo (Settings → Pages → deploy from branch) and set a custom 404. Run a broken-link check after every content change (all external links open in new tabs with rel="noopener").

Decision needed: Which suggestions to implement before publishing to GitHub Pages. Recommended minimum viable scope: B (complete key prices/hours), D (closed/moved badges), and H (publish). Map (A) and all-in cost (C) are phase 2.
